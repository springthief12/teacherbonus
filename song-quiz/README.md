# 그때 그 노래

멜론 연도별 차트 노래를 여러 명이 동시에 맞히는 실시간 웹 게임입니다.
방에 모여 연도를 고르면 그해 차트 곡이 섞여 나오고, 채팅창에 제목을 가장 먼저 친 사람이 점수를 가져갑니다.

- 화면 구성은 끄투처럼: 왼쪽 점수 순위, 가운데 문제 화면, 아래 플레이어 캐릭터 카드, 맨 아래 채팅
- 교실용: 노래는 선생님 기기(전자칠판)에서만 나오고, 학생은 휴대폰으로 답만 입력
- 글꼴: [Pretendard](https://github.com/orioncactus/pretendard) (SIL 오픈 폰트 라이선스, 무료)
- 게임 규칙은 스타크래프트 노래맞히기 유즈맵처럼: 선착순 정답, 정답 뒤에도 노래를 계속 듣다가 넘기기

> 멜론 연간 TOP 50: 2010년, 2011년, 2020년

## 바로 테스트하기 (인터넷 링크)

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/springthief12/teacherbonus)

1. 위 버튼을 누르고 깃허브 계정으로 Render에 로그인합니다. (무료, 카드 등록 없음)
2. 저장소 맨 위의 `render.yaml` 설정이 자동으로 채워지면 **Deploy Blueprint**를 누릅니다.
3. 3~5분 뒤 생기는 `https://song-quiz-xxxx.onrender.com` 주소가 테스트 링크입니다. 이 주소를 다른 사람에게 보내면 같이 플레이할 수 있습니다.

무료 서버는 15분 동안 아무도 접속하지 않으면 잠들고, 다음 접속 때 깨어나는 데 30~50초 걸립니다.
이후 깃허브에 `song-quiz` 폴더가 바뀌면 자동으로 다시 배포됩니다.

## 교실에서 켜는 법

선생님 PC 한 대가 서버가 되고, 같은 와이파이에 있는 학생 기기(크롬북·태블릿·폰)가 접속합니다.
이 게임은 실시간 서버가 필요해서 티처툴 웹사이트(Cloudflare Pages, 정적 페이지만 제공)에서는 바로 열리지 않습니다.

1. 선생님 PC에 [Node.js](https://nodejs.org) LTS 버전을 설치합니다. (처음 한 번)
2. 이 `song-quiz` 폴더를 PC에 내려받습니다. 저장소 페이지의 Code → Download ZIP 후 압축을 풀면 됩니다.
3. 윈도우는 `start-windows.bat`, 맥은 `start-mac.command` 를 더블클릭합니다.
   처음 한 번은 필요한 파일을 내려받느라 1~2분 걸립니다.
4. 브라우저에서 `http://localhost:3000` 을 열고 방을 만들면 **접속 QR**이 펼쳐집니다. 화면에 띄우면 학생들이 휴대폰 카메라로 찍어 바로 그 방에 들어옵니다.
   QR에는 `localhost`가 아니라 학생 기기가 들어올 수 있는 와이파이 주소(`http://192.168.x.x:3000/?room=방번호`)가 담깁니다.
5. 윈도우 방화벽 창이 뜨면 **허용**을 누릅니다. 학생 기기에서 안 열리면 대부분 이 단계 문제입니다.

명령어로 실행하려면:

```bash
npm install
npm start          # http://localhost:3000
```

| 환경 변수 | 설명 |
| --- | --- |
| `PORT` | 서버 포트 (기본 3000) |
| `YT_API_KEY` | 유튜브 Data API 키. 있으면 공식 API로 영상을 찾고, 없으면 키 없이 검색(yt-search)합니다 |
| `ADMIN_PASSWORD` | 음원 관리 페이지 비밀번호 (서버를 켠 PC에서 localhost로 열 때는 필요 없음) |
| `GITHUB_TOKEN` · `GITHUB_REPO` | 관리 페이지에서 고친 내용을 깃허브 저장소에도 저장 (Render용) |
| `ALLOW_NO_AUDIO` | `1`이면 음원이 없는 곡도 힌트만으로 진행 (테스트·오프라인용) |

## 게임 흐름

1. 로비에서 닉네임과 캐릭터(색·표정·소품)를 고르고 방을 만들거나 들어갑니다. 한 방 최대 8명.
2. 방장이 연도(여러 해 섞기 가능)와 규칙을 고르고 시작합니다.
3. 곡이 나오면 채팅창에 제목을 입력합니다. 오답은 채팅으로 모두에게 보이고, 정답은 가려집니다.
4. 문제 카드의 힌트 3칸이 시간에 따라 열립니다: 연도 → 가수(35%) → 제목 초성(65%). 세 칸은 언제나 같은 높이입니다. 남은 시간은 오른쪽 위 원형 타이머, 곡 진행은 맨 위 막대로 보여 줍니다.
5. 누군가 맞히면 같은 힌트 화면에서 세 칸이 모두 채워집니다(연도·순위, 가수, 전체 제목). 맞힌 사람과 점수는 위쪽에, 다음 곡까지 남은 시간은 원형 타이머에 나오고 노래는 계속 나옵니다. 넘기기 투표가 모이면 바로 다음 곡으로 갑니다.
6. 마지막 곡이 끝나면 순위를 보여 주고, 방장이 다시 시작할 수 있습니다.

넘기기: `넘기기` 버튼, 채팅창 밖에서 `K`, 또는 채팅에 `!s` / `!스킵`.

정답이 공개되면 화면에 `가수 - 노래 제목`이 같은 크기로 나오고, 왼쪽 순위판이 바로 갱신됩니다.

정답자 자리 카드에서는 폭죽이 두 번 터지고, 캐릭터가 두 팔을 흔들며 통통 뛰는 춤을 춥니다(정답 공개 시간 동안). 휴대폰에서 키보드가 올라와 자리 카드가 접혀 있으면 위쪽 정답자 표시에서 터집니다. 노래가 나오는 기기에서는 '팡' 소리가 함께 납니다. 기기에서 '동작 줄이기'를 켜 두면 폭죽과 춤은 나오지 않습니다.

### 정답 반응 속도

학생이 보낸 답이 늦게 인정되던 원인과 고친 내용입니다.

- **유튜브 검색이 게임을 멈춤 → 별도 작업 스레드로:** 다음 곡 음원을 미리 찾는 검색이 곡이 시작될 때마다 돌았는데, 검색 결과 페이지(약 1MB)를 해석하는 동안 서버가 학생들의 정답·채팅을 처리하지 못했습니다. Render 무료 서버(CPU 0.1개)와 같은 조건에서 재 보니 정답 처리가 최대 5.7초 밀렸고, 밀린 글이 한꺼번에 처리되면서 도배 방지에 걸려 사라지기도 했습니다. 검색을 별도 스레드(`server/yt-worker.js`)로 옮긴 뒤에는 같은 조건에서 최대 0.1초입니다.
- **처음부터 웹소켓으로 연결:** 예전에는 HTTP 요청을 몇 번 주고받은 뒤에 실시간 연결(웹소켓)로 바뀌었습니다. 이제 바로 웹소켓으로 연결하고, 웹소켓이 막힌 네트워크에서만 예전 방식으로 자동 전환합니다. 휴대폰 화면이 꺼졌다 켜져 다시 연결될 때도 빨라집니다.
- **보내는 즉시 내 화면에 표시:** 보낸 글이 바로 흐리게 나오고, 서버가 받으면 진하게 바뀝니다. 정답이면 내 채팅에 초록색 '정답'으로 남습니다. 연결이 불안정해 확인이 늦으면 '확인 중'이 보입니다.
- **너무 빨리 보낸 글 알림:** 3초에 6개를 넘겨 막힌 글은 줄이 그어지고, 입력창에 다시 넣어 두어 한 번만 다시 누르면 됩니다.
- **한글 키보드 남은 글자 정리:** 보내고 입력창을 비운 직후 키보드가 마지막 글자를 다시 넣는 경우(일부 안드로이드 키보드)에 그 글자를 지웁니다.

가장 빠른 구성은 교실 PC에서 서버를 켜고 학생들이 같은 와이파이로 접속하는 방식입니다(왕복 몇 ms). Render 무료 서버는 싱가포르에 있어 왕복 0.1초 안팎이 더 걸립니다.

### 소리와 효과음

- **노래:** 기본은 방장 기기(전자칠판)에서만 나옵니다. 학생 휴대폰은 노래를 틀지 않고, 유튜브 재생기도 불러오지 않습니다. 원격으로 할 때는 방 설정의 "노래 소리"를 "모든 기기"로 바꾸면 됩니다.
- **효과음:** 파일 없이 브라우저에서 만드는 짧은 소리입니다. 노래에 묻히지 않게 크게 내고, 효과음이 나는 순간에는 노래 소리를 잠깐 낮춥니다.
  - 노래가 나오는 기기에서: 게임 시작, 정답, 넘기기 표, 정답 전에 넘김, 시간 끝, 다음 곡, 게임 끝
  - 누른 기기에서: 버튼을 누를 때 작은 '톡'
  - 방 상단 **효과음 켬/끔** 버튼으로 기기마다 끌 수 있습니다.
- 학생이 정답을 맞히면 안드로이드 휴대폰은 짧게 진동합니다.

채팅은 캐릭터 머리 위에 말풍선으로 5초 동안 보입니다. 5초가 지나기 전에 새 채팅을 치면 말풍선이 바로 새 내용으로 바뀌고 다시 5초를 셉니다.

### 욕설·비속어 블라인드

채팅, 닉네임, 방 이름을 서버에서 검사해 욕설·비속어를 `*`로 가립니다. 학생이 화면을 조작해도 다른 사람에게는 가려진 채로 전달됩니다.

- 초성 표현(ㅅㅂ, ㅂㅅ, ㅈㄴ, ㄱㅅㄲ …), 띄어쓰기·숫자·기호를 끼운 변형(시 발, 시1발, ㅅ.ㅂ), 영어 자판으로 친 한글(tlqkf), 영어 욕설, 패드립·비하 표현, 손가락 욕(ㅗ, 凸)까지 잡습니다.
- 가려진 채팅을 보낸 학생에게만 "바르고 고운 말을 써 주세요" 안내가 뜹니다.
- 닉네임 전체가 욕설이면 "손님123" 같은 이름으로 바뀝니다.
- 정답 판정은 가리기 전 원문으로 하므로, 노래 제목에 쓰이는 단어 때문에 정답이 막히지 않습니다.
- "다시 발표", "21세기", "하루 세끼", "보지 마"처럼 우연히 비슷해 보이는 일상어는 가리지 않습니다.
- 표현 목록은 `server/profanity.js`, 확인용 예문은 `test/profanity.test.js`에 있습니다. 새 표현을 추가하면 `npm test`로 오탐이 없는지 확인할 수 있습니다.

### 방장 권한

- 연도·규칙 설정, 게임 시작, 다시 하기는 **방장만** 할 수 있습니다. 서버에서 막기 때문에 학생이 화면을 조작해도 바뀌지 않습니다.
- 학생 화면에는 설정 버튼 대신 현재 설정 요약만 보입니다.
- 방장은 방을 만든 사람입니다. 선생님 PC가 새로고침되거나 잠깐 끊겨도 10분 동안은 방장이 넘어가지 않고, 다시 들어오면 그대로 방장입니다.
- 선생님이 "나가기"를 누르면 임시로 다른 사람이 방장을 맡지만, 같은 기기로 다시 들어오면 방장이 돌아옵니다.

### 휴대폰에서

- 게임 중에는 문제 화면, 자리, 채팅, 입력창이 한 화면에 들어옵니다.
- 키보드가 올라오면 게임 화면을 키보드 위의 보이는 영역에 맞춰 붙이고, 자리 카드를 접어 힌트와 입력창이 함께 보이게 합니다. 보내기·넘기기를 눌러도 키보드가 내려가지 않습니다.
- 화면이 꺼지거나 다른 앱을 다녀와 연결이 끊겨도 2분 동안 자리와 점수를 지켜 두고, 돌아오면 자동으로 같은 방에 다시 들어갑니다. 새로고침해도 마찬가지입니다.
- 같은 폰에서 창을 하나 더 열면 예전 창은 로비로 나가고 자리는 하나만 유지됩니다.

### 접속 QR

- 방 상단의 **접속 QR** 버튼으로 펼치고 접습니다. 방장에게는 대기실에서 처음부터 펼쳐져 있고, 게임이 시작되면 자동으로 접힙니다.
- QR을 찍으면 `?room=방번호` 주소로 열리고, 로비에 "이 방에 들어가기" 배너가 떠서 닉네임만 정하면 바로 입장합니다.
- 와이파이 주소가 여러 개인 PC에서는 QR 아래에서 다른 주소를 고를 수 있습니다.

### 방 설정

| 항목 | 선택지 | 기본 |
| --- | --- | --- |
| 곡 수 | 10 · 20 · 30 · 50 | 20 |
| 제한 시간 | 20 · 30 · 45 · 60초 | 30초 |
| 재생 위치 | 전주부터 · 중간부터 | 전주부터 |
| 넘기기 | 과반수 투표 · 한 명이라도 · 방장만 | 과반수 |
| 점수 | 정답 10점 · 빠를수록 더(5 + 남은 초) | 10점 |
| 정답 후 듣기 | 5 · 10 · 15 · 30초 | 15초 |
| 노래 소리 | 방장 기기만 · 모든 기기 | 방장 기기만 |

### 정답 판정

- 띄어쓰기, 대소문자, 문장부호는 무시합니다. "죽어도못보내"와 "죽어도 못 보내"는 같은 답입니다.
- 괄호 속 부제와 피처링은 빼고 써도 됩니다. `잔소리 (With 2AM 슬옹)` → "잔소리", `훗 (Hoot)` → "훗", "hoot" 모두 정답.
- 영어 제목은 비슷한 한글 발음도 정답입니다. 차트 파일의 `aliases`에 적어 둔 발음과 **한 글자까지 달라도** 인정합니다.
  예) `Bad Girl Good Girl` → "배드걸굿걸", "베드걸굳걸", "뱃걸굿걸"
- 긴 영어 제목은 철자 한 글자 실수까지 인정합니다. (예: "badgirlgodgirl")
- 첫 힌트에는 연도만 나오고, 순위는 정답이 공개될 때 보여 줍니다.

## 차트 데이터

`data/charts/<연도>.json` 파일 하나가 한 해 차트입니다. 방에서는 2008~2026년만 보이고, 그중 파일이 있는 연도만 고를 수 있습니다.

```json
{
  "year": 2010,
  "source": "melon",
  "verified": true,
  "songs": [
    { "rank": 1, "title": "Bad Girl Good Girl", "artist": "미쓰에이", "aliases": ["배드걸굿걸"], "youtubeId": "선택", "start": 0, "highlight": 55 }
  ]
}
```

- `youtubeId`: 직접 지정하면 검색을 건너뜁니다. 엉뚱한 영상이 나올 때 고쳐 넣으세요.
- `start` / `highlight`: 전주부터·중간부터 모드에서 시작할 초. 없으면 0초 / 45~75초 사이 무작위.

텍스트 목록으로 한 번에 만들기:

```bash
node scripts/import-chart.js 2011 chart-2011.txt
```

한 줄에 `1. 제목 - 가수`, `제목<Tab>가수`(엑셀 복사) 같은 형식이면 됩니다.

## 음원 (소리만 재생)

화면에 영상은 나오지 않고 소리만 나옵니다. 곡마다 아래 순서로 음원을 고릅니다.

1. **직접 넣은 음원 파일** – `data/audio/2010/1.mp3`처럼 넣어 두면 그 파일을 재생합니다. 광고가 없고 모든 기기에서 같은 구간이 정확히 나옵니다. 자세한 방법은 `data/audio/README.md`.
2. **유튜브 (소리만)** – 파일이 없으면 유튜브에서 찾아 보이지 않는 재생기로 소리만 냅니다.
   뮤직비디오 대신 **노래가 바로 시작하는 음원 버전**을 고릅니다. 음반사가 올린 음원 전용 영상(채널 이름이 "가수 - Topic")을 1순위로, Official Audio를 2순위로 고르고, 뮤직비디오·티저·무대·커버는 뺍니다. 음원 버전이 하나도 없는 곡만 뮤직비디오로 대신합니다.
   광고를 줄이는 youtube-nocookie 모드를 쓰고, 그래도 광고가 끼면 광고가 끝난 뒤 다른 사람들과 같은 위치로 자동으로 맞춥니다.
   유튜브 광고를 완전히 끄는 공식 방법은 없어서, 광고 없이 쓰려면 1번 방식이 확실합니다.

찾은 영상 ID는 `data/youtube-cache.json` 에 저장해 다음부터 다시 찾지 않습니다.
삭제됐거나 퍼가기가 막힌 영상이면 다음 후보로 자동으로 바꿉니다.

## 음원 관리 페이지 (관리자)

`/admin` 주소에서 곡마다 게임에 나올 유튜브 음원을 확인하고 고칩니다.

- **들어가기:** 서버를 켠 PC에서 `http://localhost:3000/admin` 으로 열면 비밀번호 없이 들어갑니다. 다른 기기나 Render 주소에서는 `ADMIN_PASSWORD` 로 정한 비밀번호가 필요합니다.
- **곡 상태:** 확인함 · 자동 · 확인 전 · 음원 파일 · 차트 파일 · 못 찾음(셔플 제외) · 검사 전 · 제외함. 위쪽 보기에서 "확인 전"이나 "문제 있는 곡"만 따로 볼 수 있습니다.
- **확인:** 자동으로 찾은 음원을 **미리 듣기**로 들어 보고 **확인**을 누르면 그 영상으로 고정됩니다(아래쪽 미리 듣기 막대의 "이 음원 확인"도 같은 기능). 확인한 곡은 게임 중에도, "검사 안 한 곡 검사"를 눌러도 다시 검색하지 않습니다. 고정한 설정은 깃허브에도 저장되므로 Render 서버가 잠들었다 깨어나 검색 기록이 지워져도 같은 음원이 나옵니다. 영상 제목·채널도 함께 저장해 관리자 화면에 계속 표시됩니다.
- **고치기:** 유튜브 검색 후보를 보고 **미리 듣기** 후 **이걸로 선택**, 또는 유튜브 링크를 직접 붙여 넣습니다. 이렇게 고른 곡도 확인한 곡으로 고정됩니다. 고정을 풀려면 고치기 → **확인 취소**(자동 검색으로 돌아감). 앞부분에 무음·말소리가 있으면 시작 위치(초)를 정합니다. 마음에 안 드는 곡은 "셔플에서 빼기".
- **검사 안 한 곡 검사:** 수업 전에 한 번 누르면 그 연도에서 아직 검사하지 않은 곡의 음원을 미리 찾습니다. 확인한 곡, 음원 파일이 있는 곡, 셔플에서 뺀 곡은 건너뜁니다.
- 고친 내용은 바로 저장되고 다음 곡부터 반영됩니다.

### 음원을 못 찾은 곡

게임은 **음원 버전(음원 전용 영상·Official Audio)이나 음원 파일이 있는 곡만** 셔플합니다. 뮤직비디오만 있는 곡은 "못 찾음"으로 셔플에서 빠지고, 게임 중에 못 찾은 곡은 예비 곡으로 바꿔서 곡 수를 맞춥니다. 관리자 페이지에서 링크를 넣으면 다시 셔플에 들어갑니다.

### 고친 내용이 저장되는 곳

- **교실 PC:** `data/overrides.json` 에 저장됩니다. 그대로 남습니다.
- **Render 무료 서버:** 잠들거나 다시 시작하면 서버의 파일이 지워집니다. 아래처럼 깃허브에 저장하도록 설정하면 계속 유지됩니다.

#### Render에서 깃허브에 저장하기 (처음 한 번)

1. 깃허브 → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token
2. Repository access: **Only select repositories** → `teacherbonus`
3. Permissions → Repository permissions → **Contents: Read and write**
4. 만든 토큰을 복사합니다.
5. Render 대시보드 → `song-quiz` 서비스 → **Environment** 에서 두 값을 추가하고 저장합니다.
   - `GITHUB_TOKEN` = 복사한 토큰
   - `ADMIN_PASSWORD` = 관리자 페이지 비밀번호 (원하는 값)

저장 위치는 저장소의 `song-quiz-data/overrides.json` 입니다. `song-quiz` 폴더 밖이라 고칠 때마다 서버가 다시 배포되지 않습니다.
